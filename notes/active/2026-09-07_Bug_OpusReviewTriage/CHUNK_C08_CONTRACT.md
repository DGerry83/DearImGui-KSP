### Scope
Theme: widget-level correctness for the label/ID family. All guards follow the no-throw widget contract (no-op + log, never an exception) and slot in after the C01 `CanDeclareUi` gate. No public API signature changes (patch class, D36); new members are internal test seams or private helpers.

- **G2-07** (`Application/Api/DearImGuiKSP.Radio.cs`): `RadioButton(string, ref bool)` never assigned its ref — cimgui's `igRadioButton_Bool` takes `active` BY VALUE and cannot write back. The click result now applies it (`clicked → value = true`), via internal seam `ApplyRadioClick` so the assignment is unit-testable (the widget body P/Invokes; see Verification).
- **G2-08** (`Application/Api/ImGuiGradients.cs`): GradientButton drew the RAW label via `DrawListAddText`, so `##id` suffixes rendered as visible glyphs and the text was mis-centred (measured with hide-after-`##`, drawn without). The label is now stripped up front (new facade helper `StripIdSuffix`, ImGui `FindRenderedTextEnd` rule: everything from the first `##` on is identity) and the stripped text is measured, fitted, centered, and drawn. Identity is unchanged: `InvisibleButton` still receives the raw label.
- **G2-09** (`Application/DearImGuiKSP.cs` InputText + `Interop/ImGuiInternal.cs` HiddenLabelUtf8): two halves. (a) The ksp-theme path drew `Text(label)` raw — now `Text(StripIdSuffix(label))`. (b) The hidden-label ID was `"##" + label`, hashing differently from the dark path's stock `GetID(label)` (theme-dependent ID → a theme switch mid-edit dropped focus). The hidden label is now `"##" + display + "###" + label`: the leading `##` still hides the in-field label, and the mid-string `###` resets ImHashStr to the window seed (imgui.cpp:2578 sized branch / :2596 NUL-terminated branch, verified against the pinned imgui 1.92.9 in the sibling cimgui clone), so the widget ID hashes EXACTLY as the stock single-call path under every theme. The dark path is untouched (byte-identical stock).
- **G2-11** (`Application/DearImGuiKSP.cs` BeginWindow + `Application/FaultBarrier.cs`): minimal detection only, per contract. FaultBarrier now exposes the running consumer id on facade static `CurrentConsumerId` (set/restored around each callback). BeginWindow calls new internal seam `WarnOnWindowTitleCollision`: the first registered consumer to begin a title is recorded as owner (process-static `Dictionary<string,string>`); a DIFFERENT consumer beginning the same title logs one warning per title naming both consumers. Not a gate — the window still begins; no namespacing added (explicitly out of scope). BeginWindow XML doc now documents the process-global identity rule and the warning. No public API change.
- **G3-17** (`Application/Api/DearImGuiKSP.Spinner.cs`): out-of-range `SpinnerType` (cast values) indexed `s_spinnerDefaultIds[(int)type]` → IndexOutOfRangeException. Now a logged no-op (`Log?.Warn`) before the table index and dispatch, per the no-throw widget contract.
- **G3-20** (`Interop/ImGuiInternal.cs`): docs/10 §6 promises "every library widget guards" the empty-label collision with the window's own ImGui ID (ISSUES #005 family; in release the ItemAdd assert is compiled out, so the collision was silent). New `ToIdUtf8` routes all ID-bearing label/id encodes in this file (Button, SliderFloat, InputFloat, InputText, RadioButton ×2, InvisibleButton — which also covers GradientButton, BeginScrollRegion ×2, BeginTabBar, BeginTabItem, CollapsingHeader) through a shared invisible sentinel `"##dk_empty_id"` for null/empty input. Silent substitution, matching the Spinner facade's established default-ID convention (docs promise a guard, not a warning; Interop has no logger). Two empty labels in one window now collide with EACH OTHER (harmless shared-item behavior), never with the window. Raw-render paths (Text, CalcTextSize, DrawListAddText) and BeginWindow keep plain `ToUtf8` — the sentinel would render literally as text and windows are not ItemAdd items. **Known gap (out of C08's file list):** Toggle/Knob/Wheel labels in `ExtensionShimsNative.cs` and ImPlot titles in `ImPlotNative.cs` keep their own unguarded `ToUtf8` — follow-up candidate if the docs promise is to be honored literally for those widgets.
- **G3-21** (`Application/Api/DearImGuiKSP.Radio.cs`): the KSP-palette rim is now skipped under the "dark" theme (and when ThemeEngine is unwired), mirroring the InputText facade's stock-when-dark/unwired pattern — the dark preset's byte-exact-stock guarantee is preserved. `DrawRadioRimIfKspTheme` wraps both overloads' rim call.
- **G3-25** (`Application/Api/ImGuiDraw.cs`): AddText's `pos` doc corrected — ImDrawList::AddText anchors at the top-left of the text bounding box, not the baseline.
- **G3-26** (`Application/Api/ImGuiGradients.cs`): the fit-to-label path measured the label twice (two CalcTextSize calls + encodes). Now one measure of the stripped display label serves both the fit and the centering. See §5.9 verdict below.
- **G3-29** (`Interop/ImGuiInternal.cs` ToUtf8): was two byte arrays per label (encode to scratch + copy into terminated). Now one: `new byte[GetByteCount(value) + 1]` encoded straight into. Null/empty additionally returns a shared static `EmptyUtf8` (was a fresh `new byte[]{0}` per call; callers never mutate the returned buffer). C07's per-capacity InputText buffers untouched.
- **G3-31** (`Interop/ImSpinnerNative.cs`): `ImSpinnerColor` doc corrected — it mirrors C++ `imgui::ImColor` (`struct { ImVec4 Value; }`, imgui.h), which the generated cimspinner C ABI passes by value directly (cimspinner.h:125 et al.); it is NOT cimgui's `ImColor_c`. Same 16-byte layout either way; comment-only fix.
- **G3-32** (same file): SpinnerAng8 wrapper citation corrected from imspinner.h:387 to **imspinner.h:410** — verified against the vendored header (`SpinnerAng8` at line 410 with defaults bg=white, speed 2.8f, angle IM_PI, mode 0, rkoef 0.5f, matching the wrapper's constants). The `SpinnerType.Ang8` enum doc already cited 410.
- **G4-01** (`Application/Api/DearImGuiKSP.Spinner.cs`): the ISSUES #005 empty-ID guard tested only `id == null`; now `string.IsNullOrEmpty(id)` via internal seam `ResolveSpinnerLabel`, so `id: ""` takes the unique per-type default instead of colliding with the window's own ImGui ID. XML doc and the ISSUES #005 comment updated.
