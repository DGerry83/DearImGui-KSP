### Decisions Made
- 2026-09-03: M2 order is C6 → C4 → C5 (C7 parallel) so no interface stubs are needed; recorded in INTEGRATION_CONTRACT.md.
- 2026-09-04: C9/C10 serialized (was parallel group B). Both would edit the facade, `ImGuiInternal.cs`, and run concurrent native builds in the same `build/` dir — file/tool conflicts, so sequential per the parallel policy. Order: C10 then C9.
- 2026-09-04: Public widget methods (RadioButton, Toggle, later Knob/Wheel/Spinner) go on the `DearImGuiKSP` facade (as a partial class split across files), consistent with the existing Button/SliderFloat pattern. `Application/Api/ImGuiWidgets.cs` from the plan is superseded; `ImGuiGradients.cs` and `ImGuiPlot.cs` remain separate files (helpers and substantial wrapper respectively).
- 2026-09-04 (I-08 ruling): cimspinner's real generator is the Ruby `genCimSpinner.rb`, not Lua/cpp2ffi — regeneration proven byte-identical; curated SpinnerType set is drawn from upstream's config-enabled subset only (editing `cimspinner_config.h` to chase other candidates rejected — vendored byte-identity wins over a guessed candidate list).
- 2026-09-04 (I-C17-01 ruling): no public `SameLine`/layout helpers on the facade (only internal) — ThemeDemo stacks the spinner row vertically for the M5 gate. A public layout-helper surface (SameLine et al.) is a post-wave consideration, to be decided with the docs/migration work rather than grown ad hoc mid-wave.
- 2026-09-04 (C19 rulings): two more public-API gaps surfaced and were worked around, both deferred post-wave alongside the layout helpers (same decision): (1) no tooltip primitive → GraphPanel hover readout is a Text line under the grid; (2) no content-region-avail query → subplot grid is a fixed 520x360.
