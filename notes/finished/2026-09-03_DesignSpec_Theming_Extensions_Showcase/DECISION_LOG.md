# Decision Log — Pre-Release Feature Wave

Session: `notes/active/2026-09-03_DesignSpec_Theming_Extensions_Showcase/`
Numbering continues the project decision sequence (D1–D23 in `notes/finished/2026-07-29_DesignSpec_DearImGuiKSP_UI_Library/DECISION_LOG.md`). On spec confirmation these rows are appended to the project log.

| # | Date | Decision | Alternatives Considered | Rationale |
|---|------|----------|------------------------|-----------|
| D24 | 2026-09-03 | **`Application/` may reference UnityEngine.CoreModule** for `Vector2`/`Color`/`Color32` in public signatures; amends D18's "Unity-free Application" rule (scope narrowed to: no Unity engine *lifecycle/scene* APIs; the math structs are plain managed blittable types) | Library-owned blittable structs + conversion helpers in Infrastructure; primitives-only signatures | User decision (Q2-a). Consumers all reference UnityEngine already; the structs work in the plain .NET test runner, so the xUnit suite is unaffected; ergonomics win is large (no consumer-side converters). |
| D25 | 2026-09-03 | **"ksp" theme becomes the library default**; "dark" (stock ImGui) retained as an option via the existing `theme` setting | Opt-in ksp theme; ksp-only | User decision (Q1). The library's pitch is "looks like it belongs in KSP" — the default should demonstrate it. |
| D26 | 2026-09-03 | **ImGui docking branch deferred**; "complex dockable layouts" showcase intent is satisfied with multi-panel layouts (tab bars, child regions, columns) on the master branch | Switch pinned imgui to the docking branch | User decision (Q3). The docking branch is a significant native pin change with its own churn; no consumer has asked for dockable panes. |
| D27 | 2026-09-03 | **Extension selection**: ImPlot (pin v1.0 tag) via cimplot regenerated against our pinned cimgui; imgui-knobs; imgui-wheels (vendored and pinned — repo is days old, 1 star, treated as code we own); imspinner via its official cimspinner C ABI; imgui_toggle included. **HImGuiAnimation rejected** (abandoned 2024, real bugs incl. shared static delta-time buffer, pointer-centric API) — animation delivered as a C# easing/tween helper in Application instead. **implot3d deferred post-release.** | Hand-write all C ABIs; bind HImGuiAnimation; include implot3d in this wave | User decisions (Q4, Q10, Q11) + research (RESEARCH_NOTES §2). ImPlot v0.17+ carries the imgui 1.92 fixes; v1.0 is the stable pin. cimplot/cimspinner remove the largest ABI-writing cost. Wheels' immaturity is accepted knowingly: ~6 functions, we control the pin. |
| D28 | 2026-09-03 | **Gradient rendering = C#-only via existing cimgui exports**: rounded rect fill + `igShadeVertsLinearColorGradientKeepAlpha` post-shade (preserves rounding and alpha); `ImDrawList_AddRectFilledMultiColor` only where square corners are acceptable. No native changes, no gradient textures. | UV-mapped gradient textures (needs 1.92 ImTextureRef plumbing native-side); imgui_internal custom rendering | Research (RESEARCH_NOTES §2 gradients). All required functions are already exported by the pinned cimgui. Texture path rejected as needlessly invasive for a two-stop vertical gradient. |
| D29 | 2026-09-03 | **Fonts: static IBM Plex Sans Regular + Medium TTFs bundled** in `GameData/DearImGuiKSP/Fonts/` with `OFL.txt`; Noto Sans documented as user-installable alternative, not shipped; new `font` setting (default "IBMPlexSans") with embedded-ProggyClean fallback if the TTF is missing; loading via a new native export (`DearImGuiKSPNative_LoadFontFromFile`) before first NewFrame → **handshake v5** | Variable-font TTF (unsupported by stb_truetype without FreeType); ship Noto too; consumer font-loading API (stays deferred per §3.4 of the base spec) | User decision (Q8). OFL permits bundling with the license file. Font loading forces the first managed→native path string, hence the handshake bump (both sides bump in lockstep per D17). |
| D30 | 2026-09-03 | **Telemetry showcase lives inside DearImGuiKSPDemo** (one showcase package, flight-scene addon); per-stage Δv is a simplified approximation from stock-exposed data (engines/propellant per stage), labeled approximate; maneuver nodes display-only | Separate third mod/zip; stock-grade FuelFlowSimulation Δv; node creation/editing | User decisions (Q5, Q6, Q7). Showcase's purpose is demonstrating the UI library, not replacing Kerbal Engineer; precise Δv is a subsystem larger than the showcase itself. |
| D31 | 2026-09-03 | **Docs = Markdown set in `docs/`**, shipped in the release zip: getting-started, API fundamentals, widget catalog, theming, plotting, animation, IMGUI-migration, troubleshooting. XML `///` docs remain mandatory on all public members (status quo, must not regress). **No emojis or symbol glyphs anywhere in docs.** | Generated reference site (DocFX); wiki | User decision (Q9) + explicit user directive on symbols. XML docs already give IntelliSense; a site adds tooling burden with no consumer asking. |
| D32 | 2026-09-03 | **16-bit `ImDrawIdx` retained**; `RendererHasVtxOffset`/32-bit indices deferred until a demonstrated need | Enable 32-bit indices or VtxOffset now | Research + YAGNI directive. Telemetry plots (10k-point rolling lines ≈ 20k vertices) stay far under the 65k limit; only dense heatmaps/implot3d meshes approach it, and neither is in this wave. Documented as a known limit with the exact trigger. |
| D33 | 2026-09-03 | **Release gating**: release packaging (D15) runs only after this wave completes (theme, extensions, showcase, docs). **OpenGL (D20) stays deferred**; before-vs-after release decided at a decision point after the wave, based on an honest workload assessment at that time | Release before the wave; commit to GL-first now | User briefing: "we can't release without a showcase, and we can't release without good docs." The wave does not increase GL cost (all new widgets are draw-list-level, backend-agnostic). |
| D34 | 2026-09-03 | **Theme engine lives in Application** as named style presets applied by the library to the global ImGui style at startup and on settings change; consumers get bound style push/pop + gradient/draw-list helpers for local overrides | Per-window theme objects; consumer-applied themes | ImGui style is context-global; the library owns the context. Consumer local overrides compose via the stack-based style API (immediate-mode idiom). |
