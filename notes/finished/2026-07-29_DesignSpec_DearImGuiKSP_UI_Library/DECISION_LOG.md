# Decision Log — DearImGui-KSP UI Library

| # | Date | Decision | Alternatives Considered | Rationale |
|---|------|----------|------------------------|-----------|
| D1 | 2026-07-29 | **Eliminate UI Toolkit as the UI technology** | UI Toolkit (UIElements), Dear ImGui, uGUI | In Unity 2019.4, UIElements is editor-only; runtime support requires the UI Toolkit package (2020.1+ preview) which must be installed into the Unity project — impossible for a mod against the shipped KSP binary. See RESEARCH_NOTES.md §2. |
| D2 | 2026-07-29 | **Dear ImGui via native C++ plugin is the leading candidate**, pending a render-injection proof of concept | uGUI (retained mode, no native code) | Meets stated goals (performance, animation control, rich ecosystem). KSP dump shows no conflicting native-plugin usage and confirms Mono + P/Invoke availability. Risk: `GL.IssuePluginEvent` pattern unproven in KSP — must be spiked. |
| D3 | 2026-07-29 | Workflow classification: **DesignSpec** (DesignSpecRefinement.md), not ProjectBootstrap or Exploration | Exploration (tech bake-off), ProjectBootstrap | Deliverable is a design spec for a greenfield repo; tech choice is a sub-question resolved within it. ProjectBootstrap applies once the spec exists. |
| D4 | 2026-07-29 | Project name: **"DearImGui-KSP"** (no underscore); remote repo private until release | "DearImGui-KSP" | User preference. Working folder name `DearImGui-KSP` stays as-is locally; naming applies to assemblies, namespaces, and the eventual remote. |
| D5 | 2026-07-29 | **Deferred (graphics mod) compatibility is a hard requirement**; TUFX/post-processing must not break | Best-effort compatibility | User builds all mods assuming Deferred is baseline. Render injection design and the PoC must be validated against Deferred + TUFX. |
| D6 | 2026-07-29 | Platform: Windows-first, D3D11 primary + OpenGL secondary; no D3D9; DX12 assumed via D3D11 back-compat (assumption to verify); Linux/Mac long-term | Full cross-platform at launch | Matches user priorities; keeps native backend scope minimal for MVP. |
| D7 | 2026-07-29 | Demo/example mod ships as a **separate install** from the dependency library | Bundled demo | Users installing the library as a dependency must not get demo UI. |
| D8 | 2026-07-29 | C# binding: **P/Invoke against cimgui**, self-built | Hand-rolled narrow C ABI; ImGui.NET | Full widget coverage with a binding we own; no third-party binding release cadence; no prebuilt cimgui binary conflicts since we compile it. |
| D9 | 2026-07-29 | **Library-owned frame loop**: consumers register per-frame callbacks; library drives input sampling, ImGui frame, and native render handoff | Consumer-driven frames | Simpler consumer experience; single point of control for input locking and render timing. |
| D10 | 2026-07-29 | Benchmark strategy: build a **torture-test UI** in the demo mod, using IMGUI_Helper's `PerformanceTab.cs` (naive vs virtualized 1000-item list) as the reference IMGUI bog-down case | Absolute ms budgets only | User: performance hard to measure absolutely; relative demonstration vs IMGUI is the meaningful metric. |
| D11 | 2026-07-29 | State machine includes a **`Suspended` state** (game UI hidden via F2, and loading screens): no rendering, no consumer callbacks | Always-running | User-requested; avoids wasted frame work and drawing over UI-hidden screenshots/loads. |
| D12 | 2026-07-29 | **Stock ImGui dark theme only for MVP**; KSP-flavored and other themes deferred | KSP-flavored default theme in MVP | User prefers minimal MVP; theming API is still fully exposed to consumers. |
| D13 | 2026-07-29 | Default font: one bundled TTF chosen by the user with a redistribution-permitting license; consumer font-loading API deferred | Ship ImGui's embedded ProggyClean; custom fonts in MVP | Licensing must allow redistribution; user will pick the font. **Superseded by D14.** |
| D14 | 2026-07-29 | Default font: **ImGui's embedded ProggyClean** for MVP | Bundled third-party TTF (per D13) | Simplest legal option — ProggyClean ships inside ImGui itself. Font-atlas design must stay extensible since alternative font support is planned but deferred. |
| D15 | 2026-07-29 | Distribution: release zip = `GameData/DearImGuiKSP/` (`Plugins/DearImGuiKSP.dll`, `Plugins/DearImGuiKSPNative.dll`, `settings.cfg`, `LICENSE`, `README.md`, version file); demo mod as separate zip; CKAN metadata deferred | CKAN-first release | Matches KSP community norms; manual install keeps release mechanics simple for MVP. |
| D16 | 2026-07-29 | Compatibility test environment = Deferred, TUFX, Scatterer, Parallax, Cinematic Shaders, Cinematic Recorder, IMGUI mods | Minimal test matrix | These are all present in the user's deployed location; they represent the realistic render-hook-heavy baseline the library must not break. |
| D17 | 2026-07-29 | Versioning: SemVer mirrored in `KSPAssembly`/FileVersion/version file; managed+native released in lockstep; 0.x may break on minor bumps; 1.0+ freezes API within a major; `[Obsolete]` grace period before removal | Ad-hoc versioning | User deferred policy to agent. Because KSP's loader treats a higher major as satisfying a lower-major dependency, consumers should declare `KSPAssemblyDependencyEqualMajor` so a breaking 2.0 can never silently load under a 1.x consumer. |
| D18 | 2026-07-29 | Architecture: Plugin/Mod + State Machine + thin Repository + composition-root singleton; layers = native Core / managed Application / managed Infrastructure; only Infrastructure touches KSP/Unity APIs | Flat structure; event-bus-driven consumers | Matches CORE_PROTOCOLS layering rules; keeps the unproven render injection isolated in Core and testable; consumer communication is one-to-one registration, so no event bus. |
| D19 | 2026-07-29 | Native DLL deploys to `GameData/DearImGuiKSP/PluginData/`, never `Plugins/` | Native DLL in Plugins alongside managed | KSP's assembly loader tries to load every DLL in its scan path as a managed assembly; a native DLL in `Plugins/` hung the game during GameDatabase load (C1 in-game verification failure). Matches CinematicRecorder/CinematicShaders convention. |
| D20 | 2026-07-29 | **OpenGL backend deferred out of MVP**; D3D11 is the only MVP renderer. C5 (OpenGL) moves to the backlog | OpenGL validated in MVP (original spec §1.3/§3.3) | User: a meaningful GL test needs a separate environment — CinematicShaders and CinematicRecorder both fail under GL, so ReformTestInstance results would be unactionable. The GL backend design (imgui_impl_opengl3, embedded loader, 1.92.9 texture protocol) is documented and ready when a clean GL environment exists. |
| D21 | 2026-09-03 | **Viewport clamp on resolution change is player-facing library policy**, governed by a new opt-out `clampWindowsToViewport` key (default true) in the library-owned settings.cfg; spec §6.2 ("window positions are consumer state") stands unchanged for the API | Library-side unconditional clamp (amends §6.2); consumer opt-in helper only; document as immediate-mode behavior | User decision (ISSUES #002). Framing the clamp as a player setting in the library's own global config (§4.4) fixes the UX for all consumers without the library asserting layout rules over the consumer API. |
| D22 | 2026-09-03 | **uGUI click-through fixed with a library-owned invisible raycast blocker** (overlay canvas + alpha-0 full-screen Image, active only while ImGui captures the mouse, sorting layer/order adopted from the scene's topmost canvas per activation) + `MAIN_MENU` added to the mouse-capture lock mask; **IMGUI (OnGUI) click-through accepted as a documented limitation** (ISSUES #003) | Per-frame EventSystem suppression (rejected: global hammer, D5/D16 risk); per-window-rect blockers (unnecessary — WantCaptureMouse covers drags); OnGUI event-eater for IMGUI (deferred: script-order fragile, D16 risk) | ISSUES #001 fix. Stock suppression patterns are lock/raycast-based (KSPGraphicRaycaster, CanvasGroupInputLock); the blocker composes with them instead of fighting them. RaycastComparer sorts layer-before-order, so sort position must be introspected at runtime (stock values are prefab-serialized). IMGUI reads the raw event queue in OnGUI — no uGUI mechanism can intercept it. |
