# Decision Log — DearImGui-KSP UI Library

| # | Date | Decision | Alternatives Considered | Rationale |
|---|------|----------|------------------------|-----------|
| D1 | 2026-07-29 | **Eliminate UI Toolkit as the UI technology** | UI Toolkit (UIElements), Dear ImGui, uGUI | In Unity 2019.4, UIElements is editor-only; runtime support requires the UI Toolkit package (2020.1+ preview) which must be installed into the Unity project — impossible for a mod against the shipped KSP binary. See RESEARCH_NOTES.md §2. |
| D2 | 2026-07-29 | **Dear ImGui via native C++ plugin is the leading candidate**, pending a render-injection proof of concept | uGUI (retained mode, no native code) | Meets stated goals (performance, animation control, rich ecosystem). KSP dump shows no conflicting native-plugin usage and confirms Mono + P/Invoke availability. Risk: `GL.IssuePluginEvent` pattern unproven in KSP — must be spiked. |
| D3 | 2026-07-29 | Workflow classification: **DesignSpec** (DesignSpecRefinement.md), not ProjectBootstrap or Exploration | Exploration (tech bake-off), ProjectBootstrap | Deliverable is a design spec for a greenfield repo; tech choice is a sub-question resolved within it. ProjectBootstrap applies once the spec exists. |
| D4 | 2026-07-29 | Project name: **"DearImGui-KSP"** (no underscore); remote repo private until release | "DearImGui-KSP" | User preference. Working folder name `DearImGui-KSP` stays as-is locally; naming applies to assemblies, namespaces, and the eventual remote. |
| D5 | 2026-07-29 | **Deferred (graphics mod) compatibility is a hard requirement**; TUFX/post-processing must not break | Best-effort compatibility | User builds all mods assuming Deferred is baseline. Render injection design and the PoC must be validated against Deferred + TUFX. |
| D6 | 2026-07-29 | Platform: Windows-first, D3D11 primary + OpenGL secondary; no D3D9; DX12 assumed via D3D11 back-compat (assumption to verify); Linux/Mac long-term | Full cross-platform at launch | Matches user priorities; keeps native backend scope minimal for MVP. |
| D7 | 2026-07-29 | Demo/example mod ships as a **separate install** from the dependency library | Bundled demo | Users installing the library as a dependency must not get demo UI. |
| D8 | 2026-07-29 | C# binding: **P/Invoke against cimgui**, self-built | Hand-rolled narrow C ABI; ImGui.NET | Full widget coverage with a binding we own; no third-party binding release cadence; no prebuilt cimgui binary conflicts since we compile it. |
| D9 | 2026-07-29 | **Library-owned frame loop**: consumers register per-frame callbacks; library drives input sampling, ImGui frame, and native render handoff | Consumer-driven frames | Simpler consumer experience; single point of control for input locking and render timing. |
| D10 | 2026-07-29 | Benchmark strategy: build a **torture-test UI** in the demo mod, using IMGUI_Helper's `PerformanceTab.cs` (naive vs virtualized 1000-item list) as the reference IMGUI bog-down case | Absolute ms budgets only | User: performance hard to measure absolutely; relative demonstration vs IMGUI is the meaningful metric. |
| D11 | 2026-07-29 | State machine includes a **`Suspended` state** (game UI hidden via F2, and loading screens): no rendering, no consumer callbacks | Always-running | User-requested; avoids wasted frame work and drawing over UI-hidden screenshots/loads. |
| D12 | 2026-07-29 | **Stock ImGui dark theme only for MVP**; KSP-flavored and other themes deferred | KSP-flavored default theme in MVP | User prefers minimal MVP; theming API is still fully exposed to consumers. |
| D13 | 2026-07-29 | Default font: one bundled TTF chosen by the user with a redistribution-permitting license; consumer font-loading API deferred | Ship ImGui's embedded ProggyClean; custom fonts in MVP | Licensing must allow redistribution; user will pick the font. **Superseded by D14.** |
| D14 | 2026-07-29 | Default font: **ImGui's embedded ProggyClean** for MVP | Bundled third-party TTF (per D13) | Simplest legal option — ProggyClean ships inside ImGui itself. Font-atlas design must stay extensible since alternative font support is planned but deferred. |
| D15 | 2026-07-29 | Distribution: release zip = `GameData/DearImGuiKSP/` (`Plugins/DearImGuiKSP.dll`, `Plugins/DearImGuiKSPNative.dll`, `settings.cfg`, `LICENSE`, `README.md`, version file); demo mod as separate zip; CKAN metadata deferred | CKAN-first release | Matches KSP community norms; manual install keeps release mechanics simple for MVP. |
| D16 | 2026-07-29 | Compatibility test environment = Deferred, TUFX, Scatterer, Parallax, Cinematic Shaders, Cinematic Recorder, IMGUI mods | Minimal test matrix | These are all present in the user's deployed location; they represent the realistic render-hook-heavy baseline the library must not break. |
| D17 | 2026-07-29 | Versioning: SemVer mirrored in `KSPAssembly`/FileVersion/version file; managed+native released in lockstep; 0.x may break on minor bumps; 1.0+ freezes API within a major; `[Obsolete]` grace period before removal | Ad-hoc versioning | User deferred policy to agent. Because KSP's loader treats a higher major as satisfying a lower-major dependency, consumers should declare `KSPAssemblyDependencyEqualMajor` so a breaking 2.0 can never silently load under a 1.x consumer. |
| D18 | 2026-07-29 | Architecture: Plugin/Mod + State Machine + thin Repository + composition-root singleton; layers = native Core / managed Application / managed Infrastructure; only Infrastructure touches KSP/Unity APIs | Flat structure; event-bus-driven consumers | Matches CORE_PROTOCOLS layering rules; keeps the unproven render injection isolated in Core and testable; consumer communication is one-to-one registration, so no event bus. |
| D19 | 2026-07-29 | Native DLL deploys to `GameData/DearImGuiKSP/PluginData/`, never `Plugins/` | Native DLL in Plugins alongside managed | KSP's assembly loader tries to load every DLL in its scan path as a managed assembly; a native DLL in `Plugins/` hung the game during GameDatabase load (C1 in-game verification failure). Matches CinematicRecorder/CinematicShaders convention. |
| D20 | 2026-07-29 | **OpenGL backend deferred out of MVP**; D3D11 is the only MVP renderer. C5 (OpenGL) moves to the backlog | OpenGL validated in MVP (original spec §1.3/§3.3) | User: a meaningful GL test needs a separate environment — CinematicShaders and CinematicRecorder both fail under GL, so ReformTestInstance results would be unactionable. The GL backend design (imgui_impl_opengl3, embedded loader, 1.92.9 texture protocol) is documented and ready when a clean GL environment exists. |
| D21 | 2026-09-03 | **Viewport clamp on resolution change is player-facing library policy**, governed by a new opt-out `clampWindowsToViewport` key (default true) in the library-owned settings.cfg; spec §6.2 ("window positions are consumer state") stands unchanged for the API | Library-side unconditional clamp (amends §6.2); consumer opt-in helper only; document as immediate-mode behavior | User decision (ISSUES #002). Framing the clamp as a player setting in the library's own global config (§4.4) fixes the UX for all consumers without the library asserting layout rules over the consumer API. |
| D22 | 2026-09-03 | **uGUI click-through fixed with a library-owned invisible raycast blocker** (overlay canvas + alpha-0 full-screen Image, active only while ImGui captures the mouse, sorting layer/order adopted from the scene's topmost canvas per activation) + `MAIN_MENU` added to the mouse-capture lock mask; **IMGUI (OnGUI) click-through accepted as a documented limitation** (ISSUES #003) | Per-frame EventSystem suppression (rejected: global hammer, D5/D16 risk); per-window-rect blockers (unnecessary — WantCaptureMouse covers drags); OnGUI event-eater for IMGUI (deferred: script-order fragile, D16 risk) | ISSUES #001 fix. Stock suppression patterns are lock/raycast-based (KSPGraphicRaycaster, CanvasGroupInputLock); the blocker composes with them instead of fighting them. RaycastComparer sorts layer-before-order, so sort position must be introspected at runtime (stock values are prefab-serialized). IMGUI reads the raw event queue in OnGUI — no uGUI mechanism can intercept it. **"IMGUI click-through accepted as a documented limitation" superseded by D23 same day.** |
| D23 | 2026-09-03 | **IMGUI (OnGUI) click-through fixed via a GUIUtility capture grab**: an early-ordered MonoBehaviour (`DefaultExecutionOrder(-32000)`) sets `GUIUtility.hotControl`/`keyboardControl` to a reserved id on every OnGUI pass (incl. Layout) while the corresponding capture shield is up, releases to 0 iff currently ours, and additionally `Event.Use()`s mouse/keyboard events as belt-and-suspenders | CTB-style cooperative wrappers (irrelevant — the offending windows belong to other mods); v1: `Event.Use()` only + forced script order (failed in-game — dispatch ordering across runtime-loaded assemblies is unreliable); accept as documented limitation (user rejected) | ISSUES #003; spec oversight — §5.3/§10.4 never addressed mod-IMGUI input. The grab is order-independent because IMGUI itself filters controls via `GetTypeForControl` against `hotControl` (the same mechanism IMGUI uses to block controls behind an in-progress drag), and it lands in the Layout pass which every control runs. Inert when not capturing; never clobbers a foreign hotControl on release. |
| D24 | 2026-09-03 | **`Application/` may reference UnityEngine.CoreModule** for `Vector2`/`Color`/`Color32` in public signatures; narrows D18's Unity-free rule (no engine lifecycle/scene APIs — the math structs are plain managed blittable types) | Library-owned structs + Infrastructure converters; primitives-only | Wave spec Q2-a. Consumers all reference UnityEngine; structs work in the plain .NET test runner so xUnit is unaffected; avoids consumer-side converters. |
| D25 | 2026-09-03 | **"ksp" theme becomes the library default**; "dark" retained via the existing `theme` setting | Opt-in ksp; ksp-only | Wave spec Q1. The pitch is "looks like it belongs in KSP" — the default should demonstrate it. |
| D26 | 2026-09-03 | **ImGui docking branch deferred**; showcase "complex layouts" = multi-panel (tabs, child regions, columns) on master branch | Switch pin to docking branch | Wave spec Q3. Docking is a significant native pin change; no consumer demand. |
| D27 | 2026-09-03 | **Extension selection**: ImPlot (pin v1.0 tag) via regenerated cimplot; imgui-knobs; imgui-wheels (vendored/pinned — days-old repo, treated as owned code); imspinner via official cimspinner; imgui_toggle included. **HImGuiAnimation rejected** (abandoned, buggy, pointer-centric) — animation = C# easing/tween helper in Application. **implot3d deferred post-release** | Hand-write all C ABIs; bind HImGuiAnimation; include implot3d | Wave spec Q4/Q10/Q11 + research. cimplot/cimspinner remove the largest ABI cost; ImPlot v1.0 carries the imgui 1.92 fixes. |
| D28 | 2026-09-03 | **Gradients are C#-only via existing cimgui exports** (`igShadeVertsLinearColorGradientKeepAlpha` post-shade over rounded fills; `AddRectFilledMultiColor` for square-corner cases); no native changes, no gradient textures | UV gradient textures (1.92 ImTextureRef plumbing); imgui_internal custom rendering | Wave research. All needed functions already exported by the pinned cimgui; texture path needlessly invasive for two-stop gradients. |
| D29 | 2026-09-03 | **Static IBM Plex Sans Regular + Medium bundled** in `GameData/DearImGuiKSP/Fonts/` with OFL.txt; Noto Sans documented, not shipped; new `font` setting (default "IBMPlexSans"), ProggyClean fallback; new native export `LoadFontFromFile` before first NewFrame → **handshake v5** | Variable TTF (unsupported by stb_truetype); ship Noto; consumer font API (stays deferred) | Wave spec Q8. OFL permits bundling with the license file; first managed→native path string forces the lockstep bump (D17). |
| D30 | 2026-09-03 | **Telemetry showcase inside DearImGuiKSPDemo** (one package, flight-scene addon); per-stage Δv = simplified approximation from stock-exposed data, labeled "approx dV"; maneuver nodes display-only | Separate third mod; FuelFlowSimulation-grade Δv; node editing | Wave spec Q5/Q6/Q7. The showcase demonstrates the UI library; precise Δv is a subsystem larger than the showcase. |
| D31 | 2026-09-03 | **Docs = Markdown set in `docs/`** shipped in the release zip (getting-started, fundamentals, widgets, theming, plotting, animation, IMGUI migration, troubleshooting); XML `///` docs remain mandatory; **no emojis/symbol glyphs in docs** | Generated site (DocFX); wiki | Wave spec Q9 + user directive. XML docs already give IntelliSense; no consumer asked for a site. |
| D32 | 2026-09-03 | **16-bit `ImDrawIdx` retained**; `RendererHasVtxOffset`/32-bit indices deferred until a demonstrated need | Enable 32-bit indices/VtxOffset now | YAGNI. Telemetry plots (~20k verts) stay far under 65,535; only dense heatmaps/implot3d approach it — neither in this wave. Documented limit with remedy in docs. |
| D33 | 2026-09-03 | **Release gating**: release packaging (D15) only after the wave completes (theme, extensions, showcase, docs); **OpenGL (D20) stays deferred** — before/after-release decided at a post-wave decision point on an honest workload assessment | Release before the wave; commit GL-first now | User: "we can't release without a showcase, and we can't release without good docs." The wave adds no GL cost (widgets are draw-list-level, backend-agnostic). |
| D34 | 2026-09-03 | **Theme engine in Application as named global presets** (value tables + gradient params), applied at startup and on settings change; consumers override locally via bound style push/pop + gradient helpers | Per-window theme objects; consumer-applied themes | ImGui style is context-global and the library owns the context; consumer overrides compose via the immediate-mode style stack. |
| D35 | 2026-09-05 | **OpenGL ships after release.** 0.2.0.0 releases D3D11-only; OpenGL (imgui_impl_opengl3 + embedded loader + 1.92.9 texture protocol, design already documented per D20) is scheduled post-release, gated on a clean GL test environment. Docking (#011) stays behind OpenGL | GL in this release; GL before any release | Honest workload assessment (D33): the GL code work is small and backend-isolated, but validation dominates — CinematicShaders and CinematicRecorder fail under GL (D20), so the D16 instance cannot produce actionable GL results; shipping GL unvalidated would violate the failure-handling spec. The wave added zero GL cost (all widgets are draw-list-level, backend-agnostic). |
